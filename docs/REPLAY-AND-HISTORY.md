# Replaying a run, and where run history lives

`ci-review` saves everything a run produced, and `--replay` re-runs everything *after* the model calls over a saved run, for free. That makes it the cheapest way to check a change to consolidation, scoring, citations, the report or history against real model output. This page is about using it without fooling yourself: where the saved runs are, what a replay does and does not prove, and the recipes that cost nothing. For the wider ladder (replay first, then a `wide` run, then anything dearer) see [CLAUDE.md](../CLAUDE.md); the flags are in the [README](../README.md).

## Where a run's output lives

`pipeline_history/` is git-ignored and, by default, resolved relative to the working directory (`HISTORY_ROOT = "pipeline_history"`), so it is **per checkout**. With many worktrees, the run you want is in whichever directory invoked `ci-review`, often a feature worktree and not the main checkout. `configs/` and local drafts are per checkout in the same way.

**To make it one directory for every checkout, set `CI_HISTORY_ROOT`** (see [History location](CONFIGURATION.md#history-location)). `ci-review` then writes its runs, replays and daily log there, and `ci-history-report` and `ci-voice-patterns` read from there, from any worktree, so removing a worktree no longer deletes its runs. Unset, everything below is as it was. The variable is read on every call and wins over `pipeline.HISTORY_ROOT`, which is only the default.

- Each run writes, under `pipeline_history/<article-key>/`: `run_N_<timestamp>_report.json` (the full report), `_results.json` (a valid ensemble capture, which is what `--replay` reads), `_review.md` and `_worklist.md`. A replay writes to `pipeline_history/_replay/<article-key>/` instead.
- **Find a run by what it contains**, not by where you expect it: `grep -rl "<a phrase from the draft>" <your checkouts> --include='*.json'`. In Python, `glob("**")` does not descend into dot-directories such as `.claude/worktrees/` unless you pass `include_hidden=True` (3.11+); a scan that missed them came back five runs short and changed a conclusion. `find` has no such default. Search by content (`char_count` in `api_call_log`, `article_title`), because a study may file its runs under its own key.
- **Experiments go under `pipeline_history/_experiments/<name>/`, never in the article's own directory.** The next real run of an article takes the newest report in its directory as its baseline (`history.find_prior_report_path`, by timestamp alone), so a calibration or `--only-model` run filed beside the real ones silently becomes that baseline, and `ci-history-report` counts its single-model calls as never reaching consensus. Nothing reads below a top-level directory, so a nested `_experiments/<name>/` keeps the data and hides it from every reader, the way `_replay/` does. Genuine full-ensemble runs do belong in the article's directory.
- **To merge one checkout's history into another:** copy without overwriting, hash-check each file, and check before and after that `ci-history-report`'s report count moved by exactly the genuine runs and the article baselines did not move. Keep a worktree's daily log as `pipeline_<date>.<worktree>.log`; never append to the main checkout's, which another run may be writing.

## Before you remove a worktree

If `CI_HISTORY_ROOT` was set when the runs were made, their history is not in the worktree and removing it loses none of it (the run's log has a `History root:` line saying where it went). Otherwise, and for everything else a worktree holds: removing a worktree, by hand or with a tool that cleans up worktrees, deletes its git-ignored files with it: `pipeline_history/`, `configs/`, local drafts. Some tools keep a worktree only when it has *uncommitted* changes, and ignored files do not count. Runs that once changed a preset conclusion existed in exactly one worktree. Before removing one, compare its ignored directories with the main checkout's by path and size (`os.walk` and `st_size` open no file) and copy what exists only there. Worktrees can be shared between sessions, so check that nobody else is using one.

## Replaying a capture

```bash
uv run ci-review --draft <handoff> --publication <name> \
    --replay pipeline_history/<key>/run_N_<timestamp>_results.json --offline
```

- **`--replay` still needs one of the draft-loading flags** (`--draft`, `--url`, `--publish` or `--raw-draft`), although the draft's text is not used for the ensemble: the argument group is required. Use the handoff the capture was made from (`--raw-draft <draft>` for a plain draft with no handoff headers). A run prints `No model calls made; this run costs nothing.` and its summary says `Cost: $0.0000 — replayed from a capture`. `--retry-failed` takes the same flags but makes real model calls for the failed pairs, and cannot be combined with `--replay`.
- **`--offline` skips every pass that reaches the network**: LanguageTool, link validation, Wayback, citation resolution and the two SEO model calls. An offline replay's `section_9_citations` is therefore empty. To see citation-derived output, replay without `--offline` (below) or feed the saved `_report.json` through `history.save_run`.
- **A fresh worktree has no `configs/`** (it is git-ignored), so `ci-review` stops at `User config not found` before it reaches the replay. Pass `--config-dir` pointing at the main checkout's `configs/` or at a scratch copy. A scratch copy is better than creating `configs/` in the worktree, because a stale `configs/` in a worktree is a quiet way to test the wrong settings. Blank `application_password` in any copy: an offline replay never publishes.
- `--offline` also skips the grammar pass since #236 (`lt_skipped_reason: "offline"`). On an older base, an example config with `grammar_pass: true` and placeholder credentials would POST the draft to LanguageTool.

## What a replay tells you, and what it does not

- **It exercises consolidation, the report and history, and it runs the loop that builds `api_call_log`**, the `model:domain: OK/EMPTY/PARTIAL/FAILED` console lines and the `[CALIBRATION]` records. So anything in *result classification and reporting* is free to verify. It does **not** exercise the code that decides which calls to make (assignment, dispatch, retry, recovery and substitution are all skipped on a replay). Verify those live, at `--cost-preset wide`.
- **A replay's report is not an independent run.** Reports under `pipeline_history/_replay/` re-render one cached ensemble against whatever draft you name, so identical per-model counts across different articles are expected, not a bug. When measuring anything per model from history, drop `_replay/`, de-duplicate by ensemble output rather than by filename or draft, and exclude passes listed in `model_failures` (a timed-out pass contributes zero for mechanical reasons and reads as a model that found nothing).
- **Two replays of one capture are not byte-identical**, because reproducibility scoring reads the earlier runs in `_replay/<key>/`, so whichever replay runs second has one more run to compare against. Diff field by field and expect differences only in `generated`, `reproducibility.*` and each finding's `reproduced_in` and `reproduced_of`. Anything else is a real behaviour change.
- **The `Estimated cost:` log line of a replay is worked out from the captured run's calls; it is not money you spent** (the summary's `Cost: $0.0000` is the spend). With `--offline` it covers the ensemble calls only (citation verification, re-asks and SEO are skipped), so it never equals `cost_summary.total_usd` of the original report: on one capture it was $5.9559 against $6.0884, and the ensemble was 29 of 100 logged calls. When re-costing a pricing change through a replay, the figure *moving* is the signal; matching `report.json` is not. Compare like with like by filtering `api_call_log` to entries whose `pass` does not start with `citation_` or `seo_`.
- **`cost_summary.by_pass` has one row per API call**, in `api_call_log` order, not one per pass, so a lookup by pass name returns only the last call. That is right for ensemble passes (one call each), which is what makes the misread convincing. To test a saved report's accounting, re-price its log at the `pricing.yaml` that was in force when it ran (`git cat-file --filters <commit>:<path>`), not today's: re-pricing at today's table measures price changes, not accounting. Include `discarded_attempts` tokens and cached rates in any hand calculation.
- **A `--retry-failed` report with `retry_failed_from` has a trustworthy `incurred_usd`**: the capture's carried-over successes are marked `replayed` and not billed again (#211). A retry-failed report without that key predates the fix, so do not quote its cost as that run's spend.
- **A sweep over saved reports that shows zero changes may mean the captures predate the field.** Before reading anything into it, check `git merge-base --is-ancestor <commit that added the field> <branch that produced the capture>`. When no post-fix capture exists, synthesise one from a real capture (below) and always render the unmodified one as a control.
- **A worktree's `.env` is usually a placeholder** (`your_key_here`), so a live replay's per-claim relevance checks fail authentication and citations land as "fetched but could not be read". That is fine for exercising a code path and not a picture of a real run: do not quote its counts as measurements.

## Free recipes

Each costs nothing when done as described. Run the unmodified capture as the control every time: the mutated run proves the new signal fires, the intact run proves it stays silent on a healthy report, and only the pair rules out a false positive.

1. **Reproduce a failure you need.** Edit a *copy* of the capture. Deleting every `*:voice_style` key from `results` makes the replay behave as a run where that domain was never assigned. Use a scratch `--config-dir` so the real configs are never touched, and take the draft body from the sibling `_report.json`'s `corrected_draft`.
2. **Replay live without the one outward-facing side effect.** Dropping `--offline` makes citation resolution run for real (real fetches, real 403s, real archive lookups), the only way to exercise the URL-driven code paths. But `resolver._submit_missing_archives` runs unconditionally inside `resolve_citations`, with no config flag, and asks archive.org's Save Page Now to capture pages: a write to a third party that has nothing to do with what you are testing. Stub that one function, before importing `pipeline`, with a signature-agnostic stub (a fixed-arity one broke when `history_root` was added):

   ```python
   from ci_article_review.adapters.citation import resolver
   resolver._submit_missing_archives = lambda results, *args, **kwargs: print("[stub] archiving suppressed")
   from ci_article_review.pipeline import main
   ```

   A live replay is free only if the model calls fail. A worktree with *no* `.env` finds the real one by walking up, and then every relevance check and both SEO passes make real, billed calls. Stub `ci_core.llm.client._attempt` next to it: every provider call goes through `_attempt`, and a failure result needs `failed: True`, `error`, `model`, `tokens: {"prompt": 0, "completion": 0}`, `elapsed_seconds`, `raw: None` and `_terminal: True`. A throwaway worktree outside the repository tree finds no `.env` at all, and config loading then stops at `OPENAI_API_KEY is not set`; with the calls stubbed, set every `${VAR}` in the config copy to a dummy value. To ask only whether URLs got archived, use `--archive-only` instead: it makes no model call.
3. **Prove a "no network" claim by recording egress, not inferring it.** Call `pipeline.main()` from a driver that refuses *and records* every non-loopback `socket.getaddrinfo`, `connect` and `connect_ex` to a file. Set `CUSTOM_TIKTOKEN_CACHE_DIR` (to `packages/ci-core/tests/fixtures/tiktoken_cache`) and `LITELLM_LOCAL_MODEL_COST_MAP=True` *before* importing, or litellm's import-time fetches count, and write a marker line after the import so import-time and run-time attempts separate. Point `--config-dir` at a scratch copy of the two example configs (literal placeholders, no `${VAR}`, so the main checkout's `.env` never reaches `api_keys`), send history to a scratch directory (patch `pipeline.HISTORY_ROOT`, or set `CI_HISTORY_ROOT`, which wins over it), and replay a saved smoke-test capture. Run it on the *unfixed* tree first as the control. The blind spot: these patches see Python sockets only, not libcurl, so a new curl_cffi-based fetcher would slip past.
4. **Compare dependency versions.** Replay the same capture on the new lock, then `uv pip install <pkg>==<old>`, `uv run --no-sync ci-review ... --replay`, then `uv sync` to restore. Diff the two reports as described above.
5. **Section 10 without paying for `--expand`.** Add a non-failed `"perplexity:expansion"` result to a copy of `_results.json` (`data: {sources: [...], topics: [], angles: [], data_points: []}`, plus the `_model` and `_domain` keys the other entries carry), then replay with `--expand`. `_build_expansion` reads any non-failed `*:expansion` result, and `_verify_expansion_urls` then fetches each proposed URL for real.
6. **`--retry-failed`, through the real entry point.** A replay cannot reach it, because it makes the failed calls. Run `pipeline.cli()` from a driver that sets the two environment variables above, blocks every non-loopback socket call, and sets `pipeline._run_domain` to return a deep copy of *the same pass's successful result from a sibling capture of the same draft*. Pass `--offline` and `--config-dir`, `chdir` to a scratch directory so `pipeline_history/` lands there, and record the stub's calls to a file: `cli()` ends in `os._exit`, so `finally` blocks never run.
7. **See what a run will do before paying for it.** `_build_assignments` in `pipeline.py` returns the exact `(model, domain)` pairs, and `parse_metadata_only(text)` in `handoff_parser.py` shows whether a handoff parsed (the parser does not error on a malformed header, so look for empty fields). To review only some domains, put a `prompts:` list on **every model** in a copied `user.yaml` and point `--config-dir` at the copy: it is a per-model key under `models:`, not part of the publication config. Prefer it to repeated `--only-domain`, which takes one value, turns backfill off, and fragments the report and the history into one entry per domain.

8. **Before and after for a module that reads history, without swapping files.** Run master's copy as a script: `git cat-file --filters origin/master:<path> > scratch/x.py`, then `uv run python scratch/x.py --history-root <dir>`. That works for modules with no relative imports, as `history_analytics.py` has none. To get a retry-failed pair into one history inside a test, call the suite's `_stubbed_run(tmp_path, ...)` (`test_pipeline_end_to_end.py`) twice with the same `tmp_path`: first with an `extra_patches` side effect that fails one pass, then with `retry_failed_results=` that run's `*_results.json` (`TestARetryFailedRunThePipelineWrote` does this in about 0.3 s). If you do swap master's source into your tree instead, back your versions up first, and never while a suite is running against the same tree.

9. **See what citation verification is given (for example `author=`).** `--offline` empties the claims before `resolve_citations` is called, so an offline replay never reaches it. Replay without `--offline`, block sockets, stub `_attempt` as in recipe 2, and replace `ci_article_review.adapters.citation.resolver.resolve_citations` with a recorder that returns `[]`. `pipeline` imports it inside the function, so patching the module attribute before `main()` works. The recorder also stands in for `_submit_missing_archives`, which runs inside it. Replay a smoke-test capture: it costs nothing and takes about a minute and a half.

## Traps

- **A completed live replay is not proof that archiving ran.** `_submit_missing_archives` targets only citations whose Wayback lookup says `archived is False` or `snapshot_stale`. If archive.org rate-limits the availability API, the lookup returns `archived: None` and the client stops asking, so every citation falls out of the target list: the run exits 0, prints `REVIEW COMPLETE`, and never executes the submission path. When submission is what you are testing, check the outcome, not the exit code: confirm that citation entries carry an `archive_outcome`. The reliable alternatives are `--archive-only`, or driving `resolver._submit_missing_archives` directly over a prior run's citation entries with a small cap on the number of URLs, so that proving a change costs two real captures and not seventeen.
- **archive.org's two endpoints fail independently.** A `429` on the availability API and a `500` on `/save` can occur at once; a `500` from `/save` is theirs, and the code records it as `submit_failed` rather than retrying.
